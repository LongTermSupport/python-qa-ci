# Defence Before Fix conformance

Status: **partial**. This toolchain does not claim conformance. The machine-readable declaration
is `[tool.defence-before-fix]` in `pyproject.toml`, at the two levels the toolchain
specification's clause 9.1 asks for; this page is the evidence record.

Specifications: method 1.1.0, detector 1.0.0, toolchain 0.2.0
(https://defence-before-fix.github.io/).

## Toolchain MUSTs

| Clause  | Requirement                                                                                        | Status      | Evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------- | -------------------------------------------------------------------------------------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4.1     | Every detector a defence is routed through conforms                                                | Gap         | Bespoke defences are routed through Pylint only (register: green). Ruff and mypy cannot host a bespoke rule; they run off-the-shelf rules as blocking checks through the `python-qa` wrapper, which adds file subsetting, offline resolution and the record                                                                                                                                                                                                                                                                            |
| 4.2     | Every printable identifier resolves offline; pages state the correct construction                  | Partial     | `python-qa rule-doc`: bundled pages (`src/python_qa/docs/rules/`, each with a "How to fix correctly" section, test-enforced), the project's pages under `docs_dir` (enforced by `pyqaci.docs.dangling`), Pylint's message descriptions, `ruff rule <code>`. mypy codes resolve only to the one-line description mypy ships in `mypy.errorcodes`                                                                                                                                                                                        |
| 4.3     | A defence forbids every suppression route that bypasses the record                                 | Partial     | `pyqaci.suppression.unrecorded` and `.blanket` cover comment routes for Ruff (including range and file-level forms and isort action comments), Pylint, mypy (inline and file-level settings), Pyright, Bandit and Semgrep, read with `tokenize`; and the Ruff and mypy configuration settings that ignore a code, ignore errors or exclude files. Pylint's own configuration is never read, so it is no route. Not yet covered: a mypy configuration that turns a strictness flag off (`disallow_untyped_defs = false` in an override) |
| 4.4     | Local, subset-capable down to one file, identifiers printed unaltered                              | Met         | `python-qa run -p <file>`; every tool writes straight to the terminal; `tests/python_qa/test_pipeline.py`                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 4.5     | Detectors before runners; stop on a detector failure                                               | Met         | `pipeline.PHASES`; `test_detector_failure_stops_before_runners_but_every_detector_runs`                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 5.1-5.3 | Active defences listed without running them, derived from configuration, project defences included | Met         | `python-qa rules [--json]` reads Pylint's loaded checkers (bundled and project plugins), Ruff's resolved settings (`ruff check --show-settings`) and mypy's parsed options; `tests/python_qa/test_defences.py`                                                                                                                                                                                                                                                                                                                         |
| 6.1-6.3 | Record read by the toolchain; justification required, generic text rejected; record enumerable     | Met         | `qa/record.toml`, `pyqaci.record.invalid` (the documented generic check, repeated justifications), `pyqaci.record.stale`, `python-qa record list`, `python-qa rules`; beyond the specification, `pyqaci.record.budget` and `pyqaci.record.expired` keep the record small                                                                                                                                                                                                                                                               |
| 8.1     | Release fails if a bundled defence lacks documentation                                             | Met as test | `tests/python_qa/test_docs.py`: every bundled identifier has a page with the three required sections, and every page belongs to an identifier; the `docs` lane runs in CI                                                                                                                                                                                                                                                                                                                                                              |
| 8.2     | The toolchain runs its own bundled defences on its own source                                      | Met         | CI runs `python-qa run` on this repository with no Ruff or mypy configuration of its own, so the bundled defaults, the bundled Pylint plugin, the suppression scan and the record all run here as in a consuming project                                                                                                                                                                                                                                                                                                               |
